## Resultado central: reuso real já existe

A Pauta NÃO é uma implementação inteiramente paralela ao DS. Já importa `FilamentTabs`, `Section`, `InputWrapper`, `FilamentSelect`, `TableContainer`, `TableToolbar`, `Button`, `Badge` e `Dialog`. Usa também as primitives existentes `GlaTable*`, `GlaCheckbox` e `GlaRadioGroup`.

As principais divergências são de composição e de uso de variantes: quatro superfícies de filtro em vez de um card; tabela sem o header disponível; trigger de ações textual e sem Eye; detalhes excessivamente fragmentados; histórico permanentemente expandido; geometria privada aplicada aos dialogs; ações de arquivar/confirmar sem semântica danger.

Não chamar inputs nativos dentro de `InputWrapper`, nem células dentro de `GlaTable`, de “HTML cru recriado”: são a composição prevista pelas próprias primitives existentes.

## O que é componente, composição ou lacuna real

| Padrão procurado | Evidência encontrada | Decisão |
|---|---|---|
| Card / Section / Button / Badge / Select / Form Wrapper | Exports reais, usados no catálogo e já parcialmente usados na Pauta | Reusar diretamente; só mudar slots/composição necessários |
| Data Grid canônico | `TableContainer`/`TableToolbar` exportados; `GlaTable*` prontos; showcase monta `<table>` local | Não existe um export monolítico `DataGrid` que já carregue todas as regras DOR011. Isso NÃO justifica outro grid. Compor com os exports existentes |
| Table Header | `GlaTableHead`/`GlaTh` e `TableContainer.heading` | Prontos; usar |
| Tabs contidas | `GlaTabs.segmented` existe; `FilamentTabs` e amostras vivas ainda são underline | Divergência real entre briefing novo e variante atual do catálogo. Extensão mínima opt-in em `FilamentTabs`, preservando default; referência estrutural já pronta em GlaTabs |
| Confirmation Dialog | Amostra de confirmação do catálogo usa `Dialog` e `Button` | Não há wrapper `ConfirmationDialog`, mas há tudo para compor; NÃO criar infraestrutura nova |
| Icon Button | `Button size="icon"` e usos no Data Grid do catálogo | Pronto; NÃO criar `IconButton` separado |
| Empty State | Bloco local dentro do exemplo de tabela | Não exportado, mas simples composição com TableContainer; NÃO novo componente obrigatório |
| Pagination | `GlaPagination` exportado, com limitações de faixa/per-page; amostra do DS usa botões locais | Compor no slot preservando o cálculo atual; não transplantar componente incompleto para este caso |
| Popover / Column Picker | `DropdownMenu` e `DropdownMenuCheckboxItem` existem; `ui/popover.tsx` e `ColumnPicker` não encontrados | Compor picker ancorado. Dependência `@radix-ui/react-popover` instalada não equivale a wrapper DS pronto |
| Checkbox / Radio | `GlaCheckbox` e `GlaRadioGroup`; checkbox/radio nativos nos exemplos DS | Primitives reais já disponíveis; NÃO criar outra família |
| File Upload | Catálogo em linha 1768 é div visual, sem input, onDrop ou handler. Outros uploads encontrados são locais/domínio-específicos | Ausente componente genérico funcional Drag & Drop/Browse. Busca de ausência realizada nos arquivos de componentes e no restante de `src`, por exports/usos de FileUpload, Dropzone, onDrop/onDragOver, EmptyState, ColumnPicker, Popover, ConfirmationDialog, ConfirmDialog e AlertDialog. Também conferidos os exemplos efetivos e os uploads locais existentes. `ModalAnexoRelatorio` é específico de outro domínio, com campos/regras próprios: não é substituto direto do TL009.

## Partes locais que devem deixar de competir com o DS

1. Geometria `.pauta-dialog` aplicada indistintamente a leitura, formulário, aviso e confirmação. Já há casca oficial Radix; não há motivo para manter outra escala de modal.
2. Superfícies externas repetidas dos quatro filtros e ações de consulta fora do footer. Reusar Card + Section resolve sem reescrever filtros.
3. Header de tabela ausente apesar de a API `TableContainer.heading` já estar pronta.
4. Botão textual de “Ações”, apesar de `Button size="icon"` existir; Eye deve abrir diretamente TL003.
5. Identidade/dados/histórico do detalhe precisam de composição canônica, não de outro Modal/Card.
6. Confirmações e CTAs destrutivos não aproveitam as cores já existentes em Button.

A lista local de candidatos, a paginação e o upload não são provas de duplicação de componentes prontos completos. Nessas áreas a busca encontrou primitives/composições e limitações concretas; a mudança segura é recomposição, não substituição cega.
